## Findings

**#224 is covered in the current fork.** `loadEntries` throws on `parsed.errors` ([src/types.ts:135](../src/types.ts#L135)); source tests cover fatal parsing and the runtime path that preserves the previous library and clears loading ([src/__tests__/types.spec.ts:208](../src/__tests__/types.spec.ts#L208), [src/__tests__/main.spec.ts:219](../src/__tests__/main.spec.ts#L219)).

**#192 and #287 remain unresolved for citekey-only exports.** If no Zotero URI field is present, `Entry.zoteroSelectURI` falls back to `zotero://select/items/@<citekey>` ([src/types.ts:335](../src/types.ts#L335)). A test explicitly rejects assuming an eight-character citekey is a native Zotero key ([src/__tests__/metadata.spec.ts:129](../src/__tests__/metadata.spec.ts#L129)); only explicit Zotero URI metadata produces the Zotero 9 form.

**#150 remains unresolved.** A minimal input `@book{key,note={A > B and C < D}}` was replayed with parser 6.0.1: it emits `A ¿ B and C ¡ D` before `Entry.note` runs. This differs from the original entity-encoding report but still does not preserve the input. Blindly reversing those characters would corrupt genuine Spanish punctuation; making the note verbatim would lose existing TeX/link conversion. No such workaround was shipped.

**Hotkey requests remain distinct from current defaults.** #3 asks to remove plugin defaults; #8 asks for Mac-native modifiers. `CitationPlugin.init` still assigns Ctrl+Shift+O/E/R ([src/main.ts:122](../src/main.ts#L122)). #268 has a Shift+Enter secondary-template gesture but no dedicated bindable command ([src/modals.ts:318](../src/modals.ts#L318)).

**Several source changes are not full issue reproductions.** #18, #94, #106, #119, #179, #210, #217, #230, and #281 remain marked unverified or partial because the original database, platform, or third-party view was not exercised. #175 and #276 have targeted regression fixtures in `src/__tests__/metadata.spec.ts`.
